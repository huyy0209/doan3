# G3 – Bảo mật và hiệu năng nền

## Đã làm

- POST `/TaiKhoan/DangNhap` dùng fixed-window rate limit theo IP, cấu hình mặc định 10 lần / 5 phút. Tài khoản vẫn áp dụng khóa riêng sau 5 lần sai; hai lớp giới hạn xử lý theo IP và theo tài khoản.
- Request vượt giới hạn trả HTTP 429 với thông báo tiếng Việt qua trang lỗi `/Loi/429`.
- Thêm các header `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, CSP và `Permissions-Policy` cho phản hồi. CSP chỉ cho script/style cùng origin; toàn bộ inline JavaScript, style attributes và event handlers trong Views đã được chuyển/xóa, ngoại trừ payload JSON không thực thi ở view ghép lớp.
- Bật nén Brotli/Gzip kể cả HTTPS. File `/lib`, `/css`, `/js` được cache 7 ngày; các tham chiếu CSS/JS trong Views dùng `asp-append-version`.
- Thêm test HTTP cho security headers, cache file tĩnh, 429 và Gzip.

## Rà truy vấn Services

- Các truy vấn đọc trong `GiaSuService`, `HocVienService`, `HocPhiService`, `HocTapService`, `MonHocService`, `TaiKhoanService`, `ThongBaoService`, `ThongKeService`, `TongQuanService` và `CaiDatService` đã dùng `AsNoTracking` tại các luồng đọc phù hợp.
- Các `Include` còn lại phục vụ dữ liệu được hiển thị/kiểm tra hoặc thao tác cập nhật (ví dụ lớp của gia sư/học viên khi xóa, GiaSu khi xác thực đăng nhập, thanh toán khi kiểm tra công nợ). Không thấy truy vấn vòng lặp N+1 rõ ràng có thể tối ưu mà không đổi hành vi; không thay đổi service.
